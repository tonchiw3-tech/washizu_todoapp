# 追加開発 共通仕様書

## 1. todos テーブル

これまでは「列を1つも足さない・変えない」という決まりだったが、
ここからは必要であれば列を追加してよい。

ただし、目的のない列は増やさない。

## 2. 新しい機能

これまでは「仕様書に書いていない機能は作らない」という決まりだったが、
ここからは必要だと思った機能を追加してよい。

## 3. 既存の6画面

これまでは既存の6画面を変えない決まりだったが、
ここからは必要に応じて変更してよい。

ボタン、入力欄、表示項目、メッセージなども、
追加機能に必要であれば変更・追加してよい。

## 4. CSS

CSSファイルは増やさず、
既存の style.css 1枚を使用する。

必要に応じて新しいclass名を追加してよい。

ただし、今あるclass名で実現できる場合は、
むやみに新しいclass名を増やさない。

## 5. 既存機能

新しい機能を追加しても、
これまで作った機能が壊れないようにする。

以下の機能は引き続き動くこと。

- 一覧
- 登録
- 編集
- 削除
- 検索
- 並び替え
- カレンダー
- REST API
- MCP

## 6. 進め方

新しい機能を追加するときは、

1. 何を実現したいか決める
2. 必要なデータを考える
3. 変更するファイルを確認する
4. 実装する
5. 既存機能が壊れていないか確認する

という順番で進める。
